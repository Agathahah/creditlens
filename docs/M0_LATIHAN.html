Mekanisme yang sedang diuji

Jika mart dibangun ketika inputnya kosong, tabel mart menyimpan hasil kosong. Bila raw kemudian terisi, view staging dapat menampilkan baris baru, sedangkan tabel mart belum ikut berubah. Ini hipotesis mekanisme, belum kronologi yang pasti terjadi.

Tes unique memeriksa duplikasi dan not_null memeriksa nilai kosong pada baris. Tanpa baris, keduanya dapat tidak menemukan pelanggaran. Itulah alasan tes keberadaan data (nonempty) diperlukan.

03 / Praktik sekarang

Bandingkan jumlah baris sumber dan hasil

Lokasi: sesi psql Anda yang sudah terverifikasi read-only. Tetap di prompt creditlens=>; tidak perlu membuka koneksi baru.

Tujuan: melihat apakah ketimpangan staging dan mart masih terjadi sekarang. Dampak: hanya membaca; query dapat membutuhkan beberapa detik karena jumlah data besar.

Jalankan satu per satu. Salin SQL saja, tanpa tulisan prompt:

SELECT COUNT(*) FROM staging.lc_loans_clean;
SELECT COUNT(*) FROM mart.loan_features;

Output harapan: masing-masing satu angka dengan judul count. Angka tidak ditentukan sebelumnya. Jika error, simpan teks error tanpa credential dan jangan menjalankan rebuild sebagai tebakan perbaikan.

SELECT meminta hasil; COUNT(*) menghitung semua baris; FROM menentukan sumber. Nol berarti objek bisa dibaca tetapi tidak memiliki baris yang terlihat oleh query; berbeda dari error objek tidak ditemukan.

Petunjuk untuk membedakan observasi dan hipotesis

Observasi menyebut hasil yang benar-benar terlihat, lokasi, dan waktunya. Hipotesis menjelaskan mengapa hasil itu terjadi. COUNT mengukur isi sekarang; ia tidak merekam seluruh riwayat operasi tabel.

04 / Kontribusi SQL Anda

Latihan setelah hasil COUNT direview

Bagian ini dapat dikerjakan sebagai rancangan. Belum menjalankan perubahan di database aktif. Codex menyiapkan lingkungan reproduksi kecil; Anda menulis tes yang menangkap mart kosong.

A. Susun query sendiri

Tulis satu query untuk menghitung baris mart.final_features. Lalu jelaskan mengapa final dapat kosong ketika loan_features kosong.

B. Rancang tes nonempty

Konsep tes SQL dbt: query tes mengembalikan baris yang menandakan pelanggaran. Untuk kontrak wajib berisi data, rancang perilaku: input kosong menghasilkan satu baris kegagalan; input berisi data menghasilkan nol baris kegagalan.

Petunjuk pertama

Pikirkan cara menghasilkan satu nilai jumlah baris, lalu hanya mengembalikan hasil tersebut ketika jumlahnya memenuhi kondisi gagal. Perhatikan perbedaan jumlah baris data dengan jumlah baris keluaran tes.
